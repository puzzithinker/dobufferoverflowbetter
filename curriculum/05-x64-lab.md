# Module 5 — x64 stack overflow lab

## Goal

Apply the same methodology on **x64 Windows**: control `RIP`, understand stack
alignment and calling convention differences, land shellcode via a **JMP RSP**
(or equivalent) trampoline with DEP disabled.

## Why x64 feels different

| Topic | x86 | x64 |
|-------|-----|-----|
| Instruction pointer | `EIP` (4 bytes) | `RIP` (8 bytes) |
| Stack pointer | `ESP` | `RSP` |
| Return address size | 4 | 8 |
| Args | mostly stack | RCX, RDX, R8, R9 then stack |
| Address space | often low addresses | high addresses — nulls appear more often |
| mona | full classic set | many commands work; not every command is 64-bit complete |

## Tips

- Pack addresses little-endian as 8-byte values (`struct.pack('<Q', addr)`).
- Bad character `\x00` is even more painful; design payloads carefully.
- After `RET` to `JMP RSP`, confirm `RSP` points at your shellcode (alignment!).
- Use **64-bit** WinDBG session / WinDBGX auto architecture.
